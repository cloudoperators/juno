# Authentication and Access

Applications that require authentication need consistent patterns both for the sign-in flow itself and for handling the UI once users are signed in but may lack permission for certain actions or areas.

1.  [Sign In](sign-in.md) — guidelines for sign-in pages and forms: when to use a dedicated page, how to handle sign-in-specific form validation, and how to communicate failed sign-in attempts without leaking account information.
2.  [UI for Unauthorized Users](ui-for-unauthorized-users.md) — how to handle UI elements a user is not permitted to use: when to render them disabled, hide them entirely, or show an error after the fact, depending on context and available permission information.
